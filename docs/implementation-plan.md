# Promptarium 実装計画

**状態:** 実行中
**採用構成:** C# / .NET 8 / WPF / SQLite / `Microsoft.Data.Sqlite`
**更新日:** 2026-08-26

## 採用理由

- WPFはWindowsのファイル操作、クリップボード、画像表示、デスクトップ配布と親和性が高い。
- .NET標準機能で、非同期スキャン、JSON解析、暗号学的ハッシュ計算を実装できる。
- SQLiteは単一PC・1万件規模の索引、検索、ユーザー編集の保存に適する。
- 解析・データ層をWPF UIから分離し、将来のComfyUI解析器追加やテストを可能にする。

## 実装上の境界

- 元画像は読み取り専用で扱う。削除、改名、移動、再エンコードは実装しない。
- 解析できないPNGも登録可能にし、未知・破損・情報なしの状態を記録する。
- 外部API、AI推定、フォルダ常時監視、他形式対応、本格的なプロンプトビルダーは実装しない。
- 初期のComfyUI解析保証は標準的なチェックポイント／テキストエンコード／KSampler／VAE／LoRA経路までとする。実サンプルで拡張する。

## 実装上の補足決定

- `prompt` JSONがある場合はAPI promptを主解析経路とし、取得値の情報源を「ComfyUI prompt JSON」として保存・表示する。
- API promptがなく標準的なComfyUI `workflow` JSONだけがある場合は、UIワークフローのノード・リンク・ウィジェット値から限定的に導出し、「ComfyUI workflow JSON（UIワークフロー由来）」として別情報源で表示する。導出結果の状態は完全解析ではなく「一部解析」とする。
- 手動のVAE、Seed、Steps、CFG、Sampler、Scheduler、生成サイズは抽出記録とは別テーブルへ保存する。手動プロンプト／モデル／評価／メモ／タグ編集と同様、再スキャンで失われない。
- 既存カタログは起動時に非破壊のSQLite列追加で移行する。元画像と既存レコードを削除・再作成しない。

## 検証方針

- 最小有効PNGとComfyUI JSONフィクスチャを使う実行可能なスモークテストで、PNGテキストチャンク、prompt／workflow解析、タグ分割・分類、SQLite保存、重複統合、移動再照合、編集保持、旧スキーマ移行、バックアップ／復元を確認する。
- WPFアプリをビルドし、空ライブラリ、メタデータなしPNG、ComfyUI PNGの各経路を手動確認する。
- 実PNGの提供後に、解析結果を期待値フィクスチャとして追加する。
